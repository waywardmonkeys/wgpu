# Plan: Metal pipeline layout and argument buffers

## Context

- Area: mapping WebGPU bind groups and push constants to Metal resource bindings and argument buffers.
- Relevant files:
  - `wgpu-hal/src/metal/device.rs`:
    - `create_pipeline_layout`.
    - `CompiledShader` struct and its creation.
  - `wgpu-hal/src/metal/mod.rs`:
    - High-level description of how push constants, bind groups, and vertex buffers are laid out in Metal tables.

## Current behavior (wgpu Metal)

- Binding strategy:
  - Push constants, bind group 0 resources, then other bind groups, followed by vertex buffers at the end of the VS buffer table.
  - Uses `StageInfo` to track per-stage resource counts, push constant buffer indices, and a “sizes buffer” for runtime-sized arrays and vertex buffer lengths.
- Push constants:
  - Each stage that uses push constants gets a dedicated buffer slot.
  - Limits are rounded and aligned to match Metal compiler expectations.
- Storage buffer sizes:
  - For `storage` buffers and runtime arrays, wgpu passes a parallel “sizes buffer” that contains byte lengths for bounds checking and `arrayLength`.
- Argument buffers:
  - When `Features::TEXTURE_BINDING_ARRAY` is present, samplers/textures can set `support_argument_buffers`.
  - The backend exposes some support for argument buffers, but the usage is conservative and largely driven by Naga’s MSL backend expectations.

## Known issues / open questions

- Layout optimality:
  - Are we wasting binding slots or causing suboptimal compiler behavior by our chosen ordering?
  - Could push constants and sizes buffers be better packed or shared?
- Argument buffer utilization:
  - We may not be taking full advantage of Tier 2 argument buffers for large binding arrays or bindless-style patterns.
  - Apple’s WebGPU implementation may be more aggressive in grouping resources into argument buffers.
- Multi-stage interactions:
  - Ensuring consistent mapping across VS/FS/CS/TS/MS, especially when the same bind group is visible to multiple stages.

## WebKit behavior / findings

- Key WebKit references:
  - `Source/WebGPU/WebGPU/BindGroupLayout.mm`:
    - Bind group layout creation and argument buffer setup.
    - `BindGroupLayout::errorValidatingDynamicOffsets`.
    - `BindGroupLayout::bindingAccessForBindingIndex`.
  - `Source/WebGPU/WebGPU/PipelineLayout.mm`:
    - `Device::createPipelineLayout`.
    - `PipelineLayout::errorValidatingBindGroupCompatibility`.
    - Dynamic offset mapping (`updateVertexOffsets`, `updateFragmentOffsets`, `updateComputeOffsets`).
  - `Source/WebGPU/WebGPU/RenderPipeline.mm` / `ComputePipeline.mm`:
    - Render/compute pipeline creation using pipeline/layout metadata.

- Bind group layouts and argument buffers:
  - `BindGroupLayout.mm`:
    - Builds per-stage `MTLArgumentDescriptor` arrays from WebGPU binding layout entries.
    - Creates `MTLArgumentEncoder`s per stage via `newArgumentEncoderWithArguments`, storing:
      - Argument encoders for vertex, fragment, and compute stages.
      - Per-stage lists of argument indices used for each binding.
    - Encodes dynamic buffer offsets and binding sizes, with validation against `minUniformBufferOffsetAlignment` and `minStorageBufferOffsetAlignment`.
    - Maintains `sortedEntries` for deterministic iteration and binding order.
  - The result is a `BindGroupLayout` that knows:
    - How many dynamic uniform/storage buffers exist.
    - For each binding and stage, which argument buffer index and optional “buffer size” index to use (for bounds checks).
- Pipeline layout validation and usage:
  - `PipelineLayout.mm`:
    - `Device::createPipelineLayout`:
      - Validates:
        - Number of bind group layouts ≤ `maxBindGroups`.
        - All bind group layouts belong to the same device and are valid.
        - Per-stage resource counts across all bind groups obey per-stage limits:
          - Uniform/storage buffers, samplers, sampled textures, storage textures.
      - On failure, reports validation errors unless the layout is autogenerated.
    - Tracks dynamic offset layout:
      - For each stage and bind group index, computes where in the linear dynamic offset array that group’s offsets live.
      - `update{Vertex,Fragment,Compute}Offsets` and `offsetVectorForBindGroup` map WebGPU’s dynamic offsets into per-stage containers used at encoding time.
    - Validates bind group compatibility at draw/dispatch time:
      - Ensures the number of bound groups matches the pipeline’s expectation.
      - Checks that each bound `BindGroup`’s layout matches the pipeline’s `BindGroupLayout`s.
- Pipelines:
  - `RenderPipeline.mm` / `ComputePipeline.mm`:
    - Use the pipeline layout and bind group layout metadata to:
      - Bind the correct argument buffers for each stage.
      - Pass dynamic offsets and buffer sizes to shaders as needed.
    - The implementation is built around Metal’s argument buffer model; there is no separate “Naga MSL backend” layer here.

## Deltas vs wgpu (initial)

- Argument buffer usage:
  - WebKit:
    - Uses Metal’s argument buffers per-stage, per-bind-group by default:
      - Builds `MTLArgumentEncoder`s directly from `MTLArgumentDescriptor`s for each stage.
      - Maps WebGPU bindings to argument indices, including optional “buffer size” entries.
  - wgpu:
    - Primarily relies on classic buffer/texture/sampler slots mapped via Naga’s MSL backend.
    - Uses argument buffer support more conservatively (e.g. when `TEXTURE_BINDING_ARRAY` is present) and exposes it via Naga’s binding model.
- Layout validation:
  - WebKit:
    - Enforces per-stage resource limits (buffers, samplers, textures, storage textures) across all bind groups as part of `createPipelineLayout`.
    - Validates dynamic offsets and binding sizes in `BindGroupLayout::errorValidatingDynamicOffsets`.
  - wgpu:
    - Performs similar validations but in Rust/hal/core layers, and then translates to Metal bindings via Naga.
- Push constants:
  - WebKit:
    - Relies more on uniform buffers and binding layouts; there is no separate push-constant path at the WebGPU/Metal layer comparable to wgpu’s Naga-based push constant buffer insertion.
  - wgpu:
    - Treats push constants explicitly and assigns them their own buffer slots per stage, integrating them into the Metal binding model alongside bind group resources.
